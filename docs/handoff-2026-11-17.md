## 必须保留的边界

- Agent 保持普通用户会话，Linux 系统服务以登录用户身份运行，仅获得 CAP_NET_ADMIN；不默认以 root 启动整个客户端。
- 不递归 chmod/chown，不用 chmod -R 777 绕过检查；data 始终位于应用旁，不随内核更新移动。
- NoSuchUnit 不能覆盖已加载、正在运行或正在退出的证据；AccessDenied、总线故障、坏单元继续返回错误。
- 普通/服务内核共用实例锁；不能靠删除锁文件或批量按名称结束进程完成交接。
- 服务模式退出托盘后保留后台 Agent API 和内核服务，网页继续连接。
- 本轮没有增加“关闭 TUN 自动卸载服务”的新语义。关闭服务开关才执行卸载、关闭 TUN 并回到普通管理。
- 独立的上游 mihomo 二进制未改写图标；Linux/macOS 后台进程查看器是否显示桌面图标由系统决定。用户对“所有进程图标”的实际显示需求仍应在目标系统确认。

## 下次接手优先顺序

1. 先读 [context.md](../context.md)、本文件和 [status.md](status.md)，再检查目标机真实进程、端口、系统服务注册与当前设置。不要按历史 PID 清理进程。
2. 确认目标 Linux 发行版、架构、部署目录、四组件版本及 mihomo 的实际文件名/权限。先确认运行的是本次新产物，而非根目录旧 EXE 或旧服务程序。
3. 在不点击手动更新的情况下，以普通用户启动：确认选择程序旁的标准名或版本化原生 mihomo；若仍失败，查看面板保留的完整路径/探测错误，再定位，不能继续只猜权限。
4. 在目标 Linux 执行 `go test ./internal/platform/coreservice ./internal/kernelbinary ./ico`，或分别运行已交叉构建的三个测试程序；这些用例不安装/启动系统服务。已存在的 unit 格式检查依赖 systemd-analyze。
5. 完成真实服务流程：系统授权安装/修复 → 检查注册、服务就绪、单个内核和 TUN 收发 → 关闭服务并授权卸载 → 确认 TUN 关闭、委托清除、锁完成移交、普通内核单份运行 → 重复关闭不因 NoSuchUnit 失败。取消授权应保持原有服务状态。
6. 核对服务模式退出托盘后 WebUI 仍可管理，重复启动没有增加 Agent/服务/内核实例。
7. 验证新 JPEG 在目标系统的托盘、桌面、自启、通知及进程查看器中的显示；macOS 另检查 Finder/.app/Cocoa。后台进程显示受平台限制，不能仅凭图标文件已生成就报告全部完成。
8. 实测后同步 context/status/architecture/API/README 的相关描述，写明平台与实际结果。当前仅文档整理，不触发服务操作或系统授权。

若仍有现场失败，只整理必要的错误类型、脱敏路径和状态；不要把真实订阅、控制 token、完整配置或用户网络日志复制到项目文档。
